# JAS Coworking — бронирование переговорных

Система бронирования двух переговорных коворкинга **JAS Acceleration System**:

| Комната | Вместимость | Назначение |
|---|---|---|
| **Focus Room** | до 4 человек (меняется в настройках) | звонки, интервью, работа в фокусе |
| **Alfa** | до 8 человек | встречи, презентации, воркшопы |

Две части:

1. **Общая система** — `index.html`. Резиденты и гости бронируют комнату **24/7 с шагом 30 минут**.
2. **Кабинет администратора** — `admin.html`. Вход по предварительной регистрации: **максимум 3 email** и только по коду приглашения. Здесь видны все брони.

**Свой сервер не нужен.** Страницы — обычный статический сайт на **GitHub Pages**, брони хранятся в облачной базе **Supabase**. Оба сервиса бесплатные, и брони никуда не пропадают.

---

## Как включить сайт (один раз)

1. **Сделайте репозиторий публичным.** На GitHub откройте репозиторий → **Settings** → **General** → внизу **Danger Zone** → **Change visibility** → **Public**. GitHub Pages для приватных репозиториев платный. Секретов в коде нет: ключ Supabase публичный, а данные защищены в самой базе.
2. **Включите GitHub Pages.** **Settings** → **Pages** → **Build and deployment**:
   - **Source:** Deploy from a branch;
   - **Branch:** ветка с этим кодом;
   - **папка:** `/docs`;
   - нажмите **Save**.
3. Через 1–2 минуты сайт откроется по адресам:
   - бронирование: `https://golmagamedimukhammad-prog.github.io/forum/`
   - кабинет: `https://golmagamedimukhammad-prog.github.io/forum/admin.html`
4. Откройте кабинет → **Регистрация**. Введите **код приглашения**, имя, email и пароль. Код вам дали при настройке, а потом он всегда виден в кабинете → «Администраторы».

Своё доменное имя (например `booking.jas.kz`) можно подключить там же: **Settings → Pages → Custom domain**.

## Возможности

### Для резидентов и гостей
- Комнаты показаны в виде схем, у каждой живой статус: «Свободна до 15:00» или «Занята до 16:30».
- Даты на 30 дней вперёд (срок меняется в настройках). Под каждой датой полоска загрузки комнаты.
- Сетка из 48 слотов по 30 минут: ночь, утро, день, вечер.
- Чтобы выбрать время, нажмите на начало, затем на последний нужный слот. Длительность меняется кнопками −/+, бронь может переходить через полночь.
- Форма: имя, телефон, email (необязательно), резидент или гость, компания, число человек (не больше вместимости), цель встречи.
- После брони показывается код брони `JAS-XXXXXX` и кнопка «В календарь» (файл `.ics`).
- Раздел «Мои брони»: брони с этого устройства, их отмена, поиск брони по коду и телефону.
- Двойная бронь невозможна. Это проверяет сама база, даже если два человека нажмут «Забронировать» одновременно.

### Для администратора
- Регистрация **по коду приглашения**, максимум **3 email**. Когда места заняты, регистрация закрывается сама.
- **Обзор**:
  - кто сейчас в каждой комнате и до какого времени, с контактами;
  - следующая бронь по каждой комнате;
  - показатели за сегодня и на 7 дней;
  - график загрузки на неделю и лента последних действий.
- **Расписание дня** по обеим комнатам. Клик по брони открывает детали и отмену, клик по пустой ячейке создаёт новую бронь.
- **Все брони**: фильтры по периоду, комнате, статусу и типу клиента; поиск; **выгрузка в CSV для Excel**.
- **Администраторы**:
  - код приглашения: можно скопировать и сменить;
  - список занятых мест;
  - отзыв чужого доступа.
- **Настройки**: часовой пояс коворкинга, максимальная длительность брони, на сколько дней вперёд можно бронировать, названия, вместимость и описания комнат.
- Уведомление о новых бронях. Данные обновляются каждые 30 секунд.

## Где хранятся данные

Проект Supabase **«JAS Coworking Booking»** (регион — Франкфурт, бесплатный тариф).

- Посмотреть брони можно не только в кабинете, но и в панели Supabase: **Table Editor** → схема `jas` → таблица `bookings`.
- Резервная копия: **Database → Backups**, или выгрузка CSV из кабинета.
- **Засыпание базы.** Бесплатный проект Supabase засыпает, если к нему 7 дней никто не обращается. Чтобы этого не случилось, сценарий `.github/workflows/keep-alive.yml` раз в сутки делает один лёгкий запрос к базе. Работает он после того, как репозиторий станет публичным.
  - Если всё же уснёт: брони не удаляются. Достаточно нажать **Restore** в панели Supabase.
  - GitHub отключает такие сценарии в репозитории, где 60 дней не было изменений. Тогда включите его снова: **Actions** → *Supabase keep-alive* → **Enable workflow**.

### Если администратор забыл пароль

Другой администратор освобождает его место в разделе «Администраторы», и тот регистрируется заново по коду приглашения. Если администратор один, удалите его запись в панели Supabase: **Table Editor** → `jas.admins`.

## Как устроено

```
docs/                     сайт для GitHub Pages
  index.html              страница бронирования
  admin.html              кабинет администратора
  assets/config.js        адрес базы Supabase и публичный ключ
  assets/common.js        общие функции и связь с базой
  assets/booking.js       логика страницы бронирования
  assets/admin.js         логика кабинета
  assets/*.css, logo.png  оформление в стиле JAS
supabase/migrations/      схема базы: таблицы, проверки, функции
.github/workflows/        ежедневная проверка, чтобы база не засыпала
```

**Безопасность:**
- **Таблицы недоступны снаружи.** Они лежат в закрытой схеме `jas`, а сайт обращается только к функциям `public.jas_*`.
- **Публичное расписание показывает только занятое время**, без имён и контактов.
- **Данные клиентов видны только администраторам после входа.** Пароли хранятся в виде хеша (bcrypt), сессия живёт 14 дней.
- **Перебор паролей и кодов ограничен**: на вход, регистрацию и поиск брони стоит лимит попыток.
- **Двойную бронь не пропустит сама база** — это ограничение на уровне таблицы.

**Время.** Брони хранятся в часовом поясе коворкинга, его можно поменять в настройках. Гости и администраторы видят одинаковое время, где бы они ни находились.

### Локальная проверка

```bash
cd docs && python3 -m http.server 8000
```

Затем откройте http://localhost:8000. Сайт работает с той же базой Supabase.
