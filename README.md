# JAS Coworking — бронирование переговорных

Система бронирования двух переговорных коворкинга **JAS Acceleration System**:

| Комната | Вместимость | Назначение |
|---|---|---|
| **Focus Room** | до 4 человек (меняется в настройках) | звонки, интервью, работа в фокусе |
| **Alfa** | до 8 человек | встречи, презентации, воркшопы |

Система состоит из двух частей:

1. **Общая система** — `/` — страница, где резиденты и гости бронируют комнату **24/7 с шагом 30 минут**.
2. **Кабинет администратора** — `/admin` — вход по предварительной регистрации, **максимум 3 email**. Здесь видны все брони.

Оформлено в фирменном стиле JAS: оранжево-синий градиент из логотипа и шрифты Unbounded и Manrope.

---

## Возможности

### Для резидентов и гостей (`/`)
- Комнаты показаны в виде схем, у каждой живой статус: «Свободна до 15:00» или «Занята до 16:30».
- Даты на 30 дней вперёд (срок меняется в настройках). Под каждой датой полоска загрузки комнаты.
- Сетка из 48 слотов по 30 минут: ночь, утро, день, вечер. Занятые и прошедшие слоты недоступны.
- Чтобы выбрать время, нажмите на начало, затем на последний нужный слот. Длительность можно менять кнопками −/+, бронь может переходить через полночь.
- Форма: имя, телефон, email (необязательно), резидент или гость, компания, число человек (не больше вместимости комнаты), цель встречи.
- После брони показывается код брони (`JAS-XXXXXX`) и кнопка «В календарь» (файл `.ics`).
- Раздел «Мои брони» хранит брони, сделанные с этого устройства. Там же их можно отменить. Бронь, сделанную с другого устройства, можно найти по коду и телефону.
- Расписание обновляется само каждые 30 секунд. Если два человека выбрали одно время, сервер не даст создать двойную бронь.

### Для администратора (`/admin`)
- **Регистрация не больше 3 email.** Когда места заняты, регистрация закрывается сама. Если задать `ADMIN_EMAILS`, зарегистрироваться смогут только почты из этого списка.
- **Обзор**:
  - кто сейчас в каждой комнате и до какого времени, с контактами;
  - следующая бронь по каждой комнате;
  - показатели за сегодня и на 7 дней: брони, загрузка, резиденты и гости;
  - график загрузки на неделю и лента последних действий.
- **Расписание**: шкала дня по обеим комнатам с линией текущего времени. Нажмите на бронь, чтобы открыть детали, или на свободную ячейку, чтобы создать бронь.
- **Все брони**:
  - быстрые периоды и даты «с/по»;
  - фильтры по комнате, статусу и типу клиента;
  - поиск по имени, телефону, email, компании и коду;
  - **выгрузка в CSV для Excel**.
- **Карточка брони**: все данные клиента, кто и когда создал бронь, отмена с причиной.
- **Новая бронь**: например, для клиента, который позвонил по телефону.
- **Администраторы**: список занятых мест (из 3). Чужой доступ можно отозвать, тогда место освобождается.
- **Настройки**: часовой пояс коворкинга, максимальная длительность брони, на сколько дней вперёд можно бронировать, названия, вместимость и описания комнат.
- Когда клиент делает новую бронь, в кабинете всплывает уведомление. Данные обновляются каждые 30 секунд.

## Запуск

Нужен только **Node.js 22.13 или новее**. Внешних зависимостей нет: база данных — встроенный в Node SQLite.

```bash
npm start
```

Откройте:
- http://localhost:3000 — страница бронирования
- http://localhost:3000/admin — кабинет администратора. При первом входе откроется вкладка «Регистрация».

### Настройки через переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | Порт сервера |
| `DATA_DIR` | `./data` | Папка с базой `jas-booking.sqlite` |
| `TIMEZONE` | `Europe/Moscow` | Часовой пояс при первом запуске. Потом меняется в кабинете → «Настройки» |
| `ADMIN_EMAILS` | — | Через запятую: email, которым разрешено регистрироваться в кабинете. **Рекомендуется задать** |
| `TRUST_PROXY` | — | `1`, если сервер стоит за nginx или другим прокси (учитывается `X-Forwarded-For` и `-Proto`) |
| `COOKIE_SECURE` | — | `1`: cookie сессии только по HTTPS |

Пример:

```bash
PORT=8080 TIMEZONE=Asia/Almaty ADMIN_EMAILS="ceo@jas.kz,manager@jas.kz,reception@jas.kz" npm start
```

> **Важно.** Пока `ADMIN_EMAILS` не задана, зарегистрироваться в `/admin` может любой, пока не заняты все 3 места. Сразу после публикации зарегистрируйте свои почты или задайте `ADMIN_EMAILS`.

## Развёртывание

### Docker

```bash
docker build -t jas-booking .
```

```bash
docker run -d --name jas-booking -p 3000:3000 -v jas-data:/data -e TIMEZONE=Europe/Moscow -e ADMIN_EMAILS="you@example.com" jas-booking
```

### VPS (systemd или pm2) за nginx

1. Скопируйте проект на сервер и запустите `npm start`, например через `pm2 start npm --name jas -- start`.
2. В nginx проксируйте домен на `http://127.0.0.1:3000` и включите HTTPS (Let's Encrypt).
3. Задайте `TRUST_PROXY=1` и `COOKIE_SECURE=1`.

### Облачные платформы (Render, Railway, Fly.io и т.п.)

Подойдёт любая платформа с **постоянным диском**. Подключите диск и укажите `DATA_DIR` на него, иначе база будет пропадать при каждом перезапуске.

### Резервное копирование

Все данные хранятся в одном файле `DATA_DIR/jas-booking.sqlite`. Достаточно регулярно копировать его.

## Управление администраторами из консоли

Это нужно, например, если администратор забыл пароль: удалите его, и он зарегистрируется заново.

```bash
npm run admin -- list
```

```bash
npm run admin -- remove manager@jas.kz
```

## Тесты

```bash
npm test
```

Тесты проверяют:
- создание брони и защиту от пересечений, в том числе через полночь;
- шаг 30 минут, запрет брони в прошлом, вместимость комнаты;
- отмену по токену и по телефону;
- лимит в 3 администратора и отзыв доступа;
- доступ к данным только после входа, выгрузку CSV и настройки.

## Как устроено

```
server.js            HTTP-сервер, маршруты API, раздача статики
lib/store.js         база SQLite: брони, админы, сессии, настройки
lib/time.js          работа со временем коворкинга (слоты по 30 минут, часовой пояс)
public/index.html    страница бронирования
public/admin.html    кабинет администратора
public/assets/       стили, скрипты, логотип
scripts/admin-cli.js управление администраторами из консоли
tests/api.test.js    автотесты API
```

**Время.** Все брони хранятся в часовом поясе коворкинга («2026-11-26T14:00»). Гости и администраторы видят одно и то же время, где бы они ни находились. Часовой пояс задаётся в настройках.

**Безопасность:**
- пароли хешируются (scrypt);
- сессия хранится в HttpOnly-cookie;
- изменяющие запросы принимаются только как JSON — это защита от CSRF;
- на вход, регистрацию и бронирование стоит ограничение частоты запросов;
- публичное расписание показывает только занятое время, без имён и контактов.

### API

| Метод | Путь | Кто |
|---|---|---|
| GET | `/api/config` | все: комнаты, правила, текущее время |
| GET | `/api/availability?from&to` | все: занятые интервалы |
| POST | `/api/bookings` | все: создать бронь |
| POST | `/api/bookings/mine` · `/lookup` · `/cancel` | владелец брони (код + токен или телефон) |
| GET | `/api/admin/status` | все: сколько мест администратора занято |
| POST | `/api/admin/register` · `/login` · `/logout` | администратор |
| GET | `/api/admin/overview` · `/bookings` · `/bookings/recent` · `/export.csv` · `/admins` | администратор |
| POST | `/api/admin/bookings` · `/bookings/:id/cancel` · `/admins/:id/remove` | администратор |
| PUT | `/api/admin/settings` | администратор |
